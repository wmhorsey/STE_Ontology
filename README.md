# STE Ontology (Collapse-First Physics)

This repository contains an in-progress physical ontology that models matter, fields, and cosmology as consequences of a single substrate dynamic: continuous local collapse with finite throughput.

## What this project is

- A mechanistic ontology and research program
- A simulation-oriented framework (not just philosophy)
- A consolidation of several prior drafts into one working document

## Core idea in one sentence

All observable structure emerges from one substrate under collapse, plus throughput limits, resonance, cavitation, and boundary geometry.

## Current status

- Main ontology document is actively developed
- Several mechanisms are integrated and internally cross-referenced
- Open derivations and falsification targets are explicitly listed

## Scope and expectations

This repo presents a coherent model under active refinement. Some sections are working hypotheses awaiting full mathematical derivation. The intended standard is explicit assumptions, internal consistency, and testable predictions.

## Contributing & discussion rules

This section defines how feedback and disagreement are handled in this repository.

### 1) Good-faith standard

- Critique ideas, mechanisms, and derivations — not people.
- Assume good intent unless behavior clearly shows otherwise.
- Keep tone technical and specific.

### 2) What counts as useful disagreement

Useful disagreement should include at least one of the following:

- An internal inconsistency with section references
- A missing derivation step
- A conservation/causality mismatch
- A conflict with stated axioms
- A testable alternative mechanism

Short, high-signal critiques are welcome; formal structure is optional.

Preferred format for longer issues/comments:

1. **Claim being challenged**
2. **Why it conflicts** (with references)
3. **Proposed correction**
4. **What prediction changes**

### 3) What will be ignored or removed

- Personal attacks, insults, baiting, or harassment
- Drive-by dismissal without technical content
- Repetitive arguments after a documented response
- Off-topic ideological or political debates
- Spam, trolling, or bad-faith engagement

### 4) Decision policy

- The repository owner decides final merges and wording.
- Strong claims require traceable mechanism and section-level consistency.
- Open questions remain open unless supported by derivation or simulation path.
- "Disagree and commit" is acceptable after one clear technical round.

### 5) Escalation / moderation path

1. **First response**: request technical framing and references
2. **Second response**: restate scope and close non-technical thread
3. **Final step**: lock/hide/remove thread or block repeat bad-faith behavior

### 6) License to be direct

Blunt technical critique is welcome. Hostility is not.

If a comment does not meet the standards above, it may receive no response.
